## 技能导入（互联网下载）功能方案

### 数据流
1. **发现**：`POST /api/skills/import/discover` body `{ url }`
   - URL 解析：支持 GitHub 形态（`owner/repo`、完整 repo URL、`/tree/<branch>/<subdir>` 链接）→ 统一转成 `https://codeload.github.com/{owner}/{repo}/zip/HEAD`；任意 zip 直链直接用。
   - Node 内置 `fetch` 下载 zip（上限 100MB、30s 超时），`readZip` 解包到临时目录（条目名做路径穿越校验）。
   - 递归找所有 `SKILL.md`，按父目录聚合成候选技能列表 `{ name, path, description }` 返回（不入库、不写盘）。
2. **安装**：`POST /api/skills/import` body `{ url, skills: string[], targets: [{ tool, mode: 'link'|'copy' }], overwrite? }`
   - 重新下载解包（无状态服务，不做服务端缓存），把勾选的技能目录写入 `~/.agents/skills/<name>/`（共享库本体，Codex 原生发现）。已存在同名技能且未 `overwrite` 则拒绝。
   - 接入工具：按勾选对每个 tool 执行 `link`（`fs.symlinkSync(..., 'junction')`，Windows 无需特权）或 `copy`（整目录复制）。目标目录为各工具根下 `skills/`（codex/zcode/cursor/opencode/workbuddy，用 `resolveToolRoot` 定位）。已有同名链接/目录时拒绝或按 overwrite 覆盖。
   - 完成后自动触发 `runScan`（agents 源 + 相关工具源），UI 直接刷新出新技术。
3. **写权限**：两个接口都要求 `allowWrite` 开关已开启（与 /api/write 同一约束），关闭时返回引导文案。

### UI（Skills.vue）
- 头部「导入技能」按钮从 notYet 占位变成真功能：点开 `NModal` 向导——
  - 第 1 步：粘贴 URL → 调 discover → 展示候选技能（名称/描述/路径）勾选；
  - 第 2 步：接入配置矩阵——每个工具一行勾选 + n-radio-group 选「符号链接 / 目录复制」（Codex 默认建议不勾，标注"原生发现"）；
  - 安装按钮执行并展示结果（成功 N 项 / 失败原因），成功后 reload 列表。
- 「···」菜单里的「下载技能（zip）」（导出）保留不动。

### 安全与边界（non-goals）
- zip 条目防穿越（与 backup restore 同一套校验思路）；下载体积/超时上限；错误如实报。
- 不更新 `.skill-lock.json`（skills CLI 的 lock 语义留给后续版本，导入的技能在 UI 状态上表现为"目录副本"型共享库条目）。
- 不做 git 非压缩包协议、不做技能更新/版本管理、不做删除。

### 测试
- core/cli 单测风格：用 fixtures 造一个 zip（createZip 生成）模拟远端，mock fetch（注入本地 http 服务或直接传 Buffer）跑 discover/install 全流程；junction/copy 两种接入模式各断言一次。
- 真机验证：从真实 GitHub 仓库导入一个技能，勾选 ZCode 链接接入，浏览器截图确认。
